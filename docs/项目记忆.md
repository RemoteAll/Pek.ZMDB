### 性能设计与实测（2026-11-27，勿无意改回）
- `ordered.IdSet`：**负数墓碑**（`ids[i] = -id`，二分按绝对值），删除不再 `orderedRemove`；
  墓碑 ≥ 64 且不少于存活时原地压缩；`live` 字段保证 `count()` O(1)。
- `Table.ids`：表级升序 ID 表；`findAll` / 无排序字段分页 / 落盘快照直接遍历（**不要重新排序**）。
- 更新走字段 diff 快路径 `value.maybeEqualRaw`（未变化字段不 `normalize`）。
- 文本索引短键（≤128B）栈上小写折叠；重复值 insert/remove 零分配。
- 实测（10 万行，ReleaseFast）：delete 2 万次 287ms→46ms；按 ID 分页 100ms→<1ms；update 38→31ms；
  批量插入 243ms（持平）；加载 8 万行 279ms。
- 坑：给 `IdSet` 加「并行墓碑标志数组」会让插入 +20%（每行 ×6 索引各多一次 append）——
  必须用负数墓碑（零额外存储）；结论靠 A/B 实测得出。

### zzig 复用清单（别再重写）
- `zzig.db.Value`（值模型 + `asI64/asF64/asBool/asDatetime/toTextAlloc`）；本项目 `src/value.zig` 只做
  `Value → Key` 归一化（含 NaN/浮点安全检查，因为 zzig 的 `asI64` 对 NaN 会 `@intFromFloat` panic）。
- `zzig.DateTime`（parse/fromUnixSeconds/toUnixSeconds）；落库文本 `yyyy-MM-dd HH:mm:ss` 由本项目补。
- `zzig.Buf`（序列化缓冲；避开 0.17 `{d:0>4}` 输出 `+2024` 的坑，手写补零）。
- `zzig.fsio.readFileAlloc / writeFileAtomic / ensureParent`。
- `zzig.web.Value`（JSON 值树 + `jsonAlloc`）。
- `zzig.ascii`（大小写不敏感包含）。

### zzig 已知坑（实测）
- `zzig.fsio.writeFileAtomic` **不建父目录**（`ensureParent` 在 replace 阶段，晚于写 `.tmp`）：
  首次落盘会 `FileNotFound`。必须先 `zzig.fsio.ensureParent(io, path)`（本项目 `persist.writeFileAtomic` 已封装）。
- `zzig.json.Jsmn` 要求键带引号，读不了 C# 裸键 → 本项目 `src/json.zig` 自带宽容词法（`//` 注释、尾逗号）。
- `zzig.glob.matchPattern` 是路径语义（含 `/` 分段、无 `/` 只比末段），不能用于字段值通配。
- Zig 0.17 std 没有 `BTreeMap`/`Treap`，也没有 `std.Thread.Mutex`；锁要用 `std.Io.RwLock/Mutex/Condition`（都要传 `io`）。

### 架构与所有权（改代码前必读）
- 每表一把 `std.Io.RwLock`；实体堆上 `Ref(T)`（原子引用计数，对齐 Rust `Arc<T>`）。
- `insert/update/insertBatch` **失败时由库 `deinit` 传入实体**；成功时归库所有；查询结果 `List/Page/Ref` 调用方释放。
- 持久化：`persist.Hub`（Mutex+Condition+最小间隔）+ 后台线程；纯内存实例（`base_dir=""`）不置脏、`flush` 直接返回。
- `AnyTable` vtable：`destroy/clear/isDirty/markDirty/saveTo/statistics`；`MemoryDb.clearAll` 依赖 `markDirty`。
- 快照：按 ID 升序；`pretty=false` 为单行 `[ { ... } ]`。
